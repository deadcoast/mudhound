# crown-context

When mapping codebase context, referencing specific code locations, understanding quadrant organization, tracing integration paths, or feeding repository information into crown documents, this skill provides the context management specification.

---

## Purpose

crown-context teaches how to:
1. Reference specific code locations in documents
2. Organize codebases into logical quadrants
3. Trace integration paths for unused code
4. Feed codebase context into findings and tasks
5. Maintain repository knowledge mapping

---

## Codebase Reference Format

### Symbol Location

```markdown
**Location:** `file/path.py:45`
**Symbol:** `function_name`
**Type:** Function/Class/Method/Variable
**Exported:** Yes/No
**References:** N (or list locations)
```

### Full Context Block

```markdown
**Context:**
- Module: caching
- Related symbols: CacheManager, cache_store
- Git history: Added commit abc123 "Add cache"
- Comments: "Calculate cache key for results"
- TODOs: None found
```

### Integration Path

```markdown
**Integration Path:**
1. Import in `engine.py` line 15
2. Call from `SearchEngine.search()` line 89
3. Store result in `result_cache`
4. User receives cached response
```

## Quadrant System

### Default Configuration

| Quadrant | Purpose | Patterns |
|----------|---------|----------|
| Q1 | Core Logic | core/, lib/, adapters/, models/ |
| Q2 | User Interfaces | cli/, commands/, cmd/, api/ |
| Q3 | Visual Elements | ui/, components/, views/, frontend/ |
| Q4 | Support | tests/, utils/, helpers/, logging/ |

### Quadrant Detection

During `/crown:init`:
1. Scan project directories
2. Match against patterns
3. Count files per quadrant
4. Report uncategorized

### Customization

In Docs/crown.md:
```markdown
**Quadrants (customized):**
- Q1: src/core/, src/adapters/
- Q2: src/cli/, bin/
- Q3: frontend/
- Q4: tests/, scripts/
```

## Tracing Integration Paths

### Method

1. **Start at unused symbol**
   ```
   calculate_cache_key() in core/cache.py
   ```

2. **Find potential callers**
   - What module would use this?
   - What workflow would benefit?
   - Search for related functionality

3. **Trace to entry point**
   ```
   cache → engine → search command → CLI → user
   ```

4. **Identify missing link**
   ```
   cache ──✗── engine (missing import/call)
   ```

5. **Document path**
   ```markdown
   **Integration Path:**
   1. Import in engine.py
   2. Call from search() method
   3. Connect to user workflow
   ```

## Context Best Practices

### DO
- Include file:line locations
- Show relevant code snippets
- List related symbols
- Document git history
- Trace full integration path

### DON'T
- Copy entire files
- Include unrelated code
- Skip investigation step
- Assume without evidence
- Delete without integration attempt
